Production-speed parameter work

High-Density Parameter Workspace

Built for the enormous parameter interfaces that technical Houdini work actually produces.

Complex nodes can expose hundreds or thousands of controls. Pragmatic Workflow replaces the conventional vertical parameter flow with a custom Qt workspace built around spatial grouping, direct interaction, and information density. Related controls stay close together, compatible operations can share a row when it helps, and the interface spends screen space on useful state instead of empty padding.

The point is not to make everything tiny. It is to make a large node readable at a glance and fast to operate. Navigate long interfaces fluidly, collapse structure when you do not need it, use compact control-specific interactions, and keep the panel responsive even on unusually heavy parameter layouts.

High information density Spatial grouping Direct micro-interactions Fast navigation Dynamic dependencies Responsive on huge nodes Parameter-state feedback Integrated code intelligence

Technical development

Context-Aware IDE

Write VEX, OpenCL, Python, and C++ without dropping back to a basic parameter text editor.

A Monaco-powered editor brings completion, signature help, hover documentation, symbol navigation, API information, and context-sensitive suggestions directly into the parameter workflow. The code stays next to the node and scene it affects instead of turning every edit into a trip to another tool.

The intelligence changes with the language and context: dedicated VEX semantics, Houdini-aware OpenCL bindings, HOM typing for Python, and C++/HDK integration with the native toolchain. It is not one generic autocomplete layer stretched across four languages.

Dedicated VEX intelligence OpenCL binding context Python + HOM typing C++ + HDK integration Completion & signatures Hover documentation Symbol navigation

Pragmatic Node Info

See what the node changed instead of comparing two blocks of statistics by eye.

Pragmatic Node Info turns MMB inspection into a change report. Compare against available input data to surface attributes and groups that were created, modified, deleted, or left unchanged, and flag topology changes separately so structural edits do not disappear inside a wall of metadata.

Memory deltas show where the footprint moved across attributes, groups, and VDBs. For VDB work, inspect reported tree, metadata, and transform touches alongside the volume state. The question becomes simple: what did this node actually touch?

Attribute changes Group changes Topology changes Per-attribute memory delta Per-group memory delta VDB memory delta VDB touch state Attribute visualizers

Touch and revision indicators report changed state where available; they are not a per-element value diff.

Stop running out of hotkeys

Context-Aware Action System

One key can resolve to different operations from the current network, modifiers, selection state, and your own Python logic.

Memorizing a separate shortcut for every script, recipe, and node action does not scale. Build rules around the current network context, Ctrl/Alt/Shift/Space modifiers, and selected versus unselected state so the same key can do the appropriate thing for the task in front of you.

Rules can execute custom Python functions or expressions with the originating UI event, create operators, run supported recipes and shelf tools, or open custom menus at the cursor. When the built-in conditions are not enough, your Python can inspect Houdini and make the decision.

Network-context rules Modifier rules Selection-state rules Python event logic Operator creation Recipes & shelf tools Custom menus

Edit the graph over the result instead of making the network and viewport fight for screen space.

Traditional pane layouts divide the screen between the graph and the viewport. ONE layers the Network Editor directly over the 3D view, so both can use the same working area. Hardware pressure at a glance

Resource Monitor

Keep CPU, RAM, GPU, and VRAM in peripheral vision while you work.

Pragmatic Resource Monitor puts live system telemetry directly in the Houdini workspace. Watch CPU, system RAM, GPU, and VRAM pressure during heavy simulations, procedural generation, large scenes, or GPU workflows without maintaining a separate monitoring setup.

An optional cook timeline adds context about cook activity observed by Workflow. Choose from compact rings or more expressive liquid, segmented, ribbon, and thermal gauges, then tune the presentation so the telemetry stays readable without becoming the interface.

CPU System RAM GPU VRAM Optional cook timeline Six gauge styles Configurable presentation

Telemetry shows system pressure; it does not assign GPU or RAM usage to an individual node.

Follow the expensive work

Advanced Performance Profiler

Move from a hotspot into the relationships behind it.

Pragmatic Workflow turns captured Houdini performance data into a modern investigation workspace. Start from expensive recorded work, then trace it through event call trees, bottom-up caller views, flame graphs, and direct node navigation.

Separate VEX program reports keep code-level investigation from getting buried inside general SOP evaluation. Instead of stopping at a timing table, move through the recorded callers and surrounding events, then jump back to the node you need to inspect.

Hotspot analysis Event call trees Bottom-up callers Event flame graphs VEX program reports Direct node navigation

Event analysis follows Houdini's captured performance data rather than source-level CPU sampling.

NATIVE DEVELOPMENT

Native development

C++ & HDK Development

Go from toolchain setup to a verified native build without turning environment setup into its own project.

Start the supported native-development setup from inside Workflow, guide the required compiler and environment configuration, then verify the result with a fresh HDK compile, native load, and function-call check. When verification passes, you know the environment can actually build and load Houdini-native code.

The same C++ environment feeds Workflow's HDK-aware language intelligence. If you also use Pragmatic Operators, pair it with C++ Wrangle to write, compile, and iterate on native node logic directly in the scene.

Guided toolchain setup Real HDK compile check Native load verification C++ / HDK intelligence

C++ Wrangle is part of Pragmatic Operators and is sold separately from Workflow.

What is included with Workflow?

Workflow includes the systems described on this page: High-Density Parameter Workspace, Context-Aware IDE, Pragmatic Node Info, Context-Aware Action System, Overlay Network Editor, Resource Monitor, Advanced Performance Profiler, C++ & HDK Development, and their supporting workflow tools. How does licensing work?

Individual licenses are assigned to one named customer, support one concurrent seat and up to two activated devices, and include 12 months of update coverage. Eligible releases remain usable permanently. Studio licensing uses a floating concurrent seat pool sized to the purchased tier.

Can I customize the interface?

Yes. Verified options include density and layout, supported interaction preferences, overlay behavior, timeline interaction, Resource Monitor presentation, and other component-specific UI preferences. Available options vary by component.

How is Workflow different from Suite?

Workflow is the workspace and productivity product. Pragmatic Suite combines Workflow with Pragmatic Operators under the broader bundle offer. Operators is not included in a standalone Workflow license.
