Parameter workflow

Advanced Parameter Workspace

A redesigned parameter UX for complex Houdini work.

Pragmatic Workflow rebuilds the parameter-working experience around complex Houdini nodes: dense control-specific layouts, deliberate grouping, compact path/string/menu treatments, configurable labels, collapsible structure, parameter-state feedback, and fine control over typography and spacing.

The result is a higher-information workspace without reducing everything to tiny text. Related controls stay visually organized, density can be tuned to the display, and code-bearing parameters connect directly to Workflow's integrated language-intelligent development environment.

Dense configurable layouts Control-specific UX Grouping and hierarchy Expressions and parameter state Ramps and multiparms Typography and spacing Language-intelligent code integration

First-class development environment

IDE-Grade Development Environment

Dedicated language intelligence for VEX, OpenCL, Python, and C++ inside Houdini.

Workflow turns code-bearing parameters into a first-class development environment with completion, signature help, hover documentation, symbol navigation, API information, and Houdini-specific context directly in the editing surface.

Each language is treated as its own development environment. VEX uses a dedicated language service instead of a generic C-like parser. OpenCL can understand Houdini binding context. Python works with HOM typing information. C++ connects to HDK, native build tooling, and the development environment. Monaco supplies the editing foundation, while Workflow supplies the Houdini-specific intelligence around it.

Dedicated language services VEX semantic intelligence OpenCL binding-aware intelligence Python and HOM typing C++ and HDK integration Completion and signature help Hover documentation Symbol navigation

Keep technical reasoning inside Houdini. Language capabilities differ by context, and C++ requires the appropriate HDK and toolchain environment. Workflow does not generate code for you.

What did this node change?

Pragmatic Node Info & Change Tracking

See what a node created, modified, deleted, touched, and how its memory footprint changed.

Pragmatic Node Info turns quick node inspection into a change report. Compare against available input data to classify attributes and groups as created, modified, deleted, or unchanged, and surface topology changes separately so structural edits are immediately visible.

Memory deltas show how much memory was added or removed, including per-item changes for attributes, groups, and VDBs. For VDB data, Node Info also exposes the relevant VDB state and touch information, including reported tree, metadata, or transform revisions. This turns MMB-style inspection into a focused answer to the question: what did this node actually touch?

Created / modified / deleted attributes Created / modified / deleted groups Topology change detection Per-attribute memory delta Per-group memory delta VDB change & memory delta VDB tree / metadata / transform touches Attribute visualizers

Debug from the node outward. First identify what the node changed and where the memory moved, then inspect underlying values only when you need them. Touch/revision signals identify changed state; they are not a value-by-value diff of every element.

Programmable interaction

Context-Sensitive Hotkey & Action System

One key can resolve to different operations from the network context, modifiers, selection state, and your own Python logic.

Build rules around the current network context, Ctrl/Alt/Shift/Space modifiers, and whether something is selected. A single configured key can resolve to different operations across supported network types and working states instead of becoming another isolated shortcut to memorize.

Rules can execute your own Python functions or expressions with access to the originating event, run supported recipes and shelf tools, create operators, or open custom menus. Custom Python can inspect Houdini in more detail when the built-in conditions are not enough.

Context rules Modifier rules Selection-state rules Arbitrary Python calls Recipes and shelf tools Custom menus

This is programmable interaction with Houdini, not merely a replacement shortcut list. ONE is optional; the Hotkey System also works in a normal Network Editor.

Immersive workspace

Overlay Network Editor

A full-size viewport and node network in the same screen space.

A side-by-side layout makes the viewport and network compete for space. ONE overlays the network on the viewport, so a large graph does not require a small view of your result. Make a change where you are already looking and see its effect in that same area without repeatedly moving your attention between separate panes or monitors.

Combine ONE with fullscreen mode and the integrated Parameter Editor for an immersive Houdini workspace: a large viewport, your graph over it, and the controls you need close by. On a laptop, every reclaimed pane matters. On a large monitor, the same arrangement gives both the scene and graph room while keeping the edit and result loop together.

System telemetry

Resource Monitor

Live CPU, RAM, GPU, and VRAM telemetry in a customizable Houdini HUD.

Pragmatic Resource Monitor keeps live CPU, RAM, GPU, and VRAM telemetry visible in a compact Houdini HUD, giving you an immediate read on system pressure while you work.

Choose Ring, Liquid, Radiant Liquid, Segmented Arc, Ribbon Sweep, or Thermal Bloom, then configure resource colors, typography, scale, spacing, opacity, and supported animation behavior. An optional cook timeline can show the cook activity observed by Workflow's notification hooks.

CPU, RAM, GPU, VRAM Six gauge styles Optional cook timeline Per-resource colors Typography and layout controls

Telemetry availability varies by hardware and platform. System-wide GPU and RAM readings are not exact per-node resource ownership.

Deep performance analysis

Advanced Performance Profiler

Turn Houdini performance data into a real investigation.

Pragmatic Workflow turns captured performance data into a deeper investigation workspace. Start from hotspots, then trace recorded work through an event call tree, bottom-up caller analysis, flame graphs, and direct node/path actions.

Separate VEX program reports add another layer for technical investigation. The goal is to move from “this is expensive” toward understanding how the recorded work relates, where it came from, and what to inspect next.

Hotspot-oriented analysis Event call tree Bottom-up callers Event flame graphs Recorded-node navigation VEX program reports

From hotspot to cause. Workflow turns captured performance data into a structured profiling workspace for investigation. Event views represent captured event work rather than source-level CPU sampling, and Workflow does not claim to make Houdini faster merely by being installed.

Native development

Native C++ & HDK Development

From Houdini to a verified native build environment.

The HDK already ships with Houdini, and SideFX documents hcustom, CMake, and the compiler requirements for native plugins. Workflow's contribution is not a replacement SDK; it brings guided toolchain setup and verification into Houdini itself.

One setup action starts the supported compiler/toolchain setup flow and then verifies the environment with a fresh HDK compile, native load, and function-call check. Workflow's C++ editing environment then connects that verified native setup to its HDK language intelligence.

Guided native toolchain setup Real HDK compile verification Native load and function-call check C++ and HDK language intelligence

Using Pragmatic Operators too? Pair Workflow with C++ Wrangle to write, compile, and iterate on C++ node logic directly inside Houdini. C++ Wrangle is part of Pragmatic Operators and is sold separately from Workflow.
