Start with the systems most likely to change how almost every Houdini artist works.

Fluid parameter work

High-Density Parameter Workspace

Built for nodes with hundreds or thousands of parameters.

Large Houdini nodes often become long vertical interfaces. Workflow reorganizes that space around the task: related controls sit together, compatible operations can share a row, labels stay close to their values, and useful state gets screen space instead of generic padding.

The interaction model goes beyond layout. Surface evaluated expressions and parameter state directly in the interface, drag through long panels and tab headers, collapse structure when it is not needed, and use swiping, sliding, keys, or conventional clicks depending on the control. The custom Qt implementation is also tuned to remain responsive on unusually large parameter sets.

High information density Spatial grouping State at a glance Drag navigation Collapsible structure Direct micro-interactions Responsive heavy nodes Integrated IDE

In development · Network understanding

Graph Lenses

Ask a different question of the same graph without changing the graph.

Graph Lenses are designed as non-destructive views over the same Houdini graph. Switch the network from its normal presentation into focused views for structure, data relationships, memory, changes, or recorded cook evidence while preserving the underlying nodes and connections.

A lens can collapse irrelevant branches, surface nested HDA relationships, expose indirect dependencies, or emphasize the parts of a graph relevant to the question you are asking. Recorded-cook views would use captured performance evidence where available rather than pretending to reconstruct an exact live execution path.

Structure lens Data lens Memory lens Change lens Recorded-cook lens Semantic zoom

In development · Change review

Visual Graph Diffing

Compare two network states the way developers compare code.

Graph Diffing is aimed at making structural Houdini changes reviewable at a glance: nodes created or removed, connections changed, parameters edited, and branches reorganized between two states.

The goal is to make HDA iteration, branch experiments, version reviews, and regression debugging easier to reason about without manually scanning two nearly identical networks.

Added / removed nodes Connection changes Parameter changes Branch comparison Version review

In development · Hierarchy navigation

Continuous Hierarchy Zoom

Move through nested networks without repeatedly diving in, backing out, and rebuilding your mental map.

Continuous Hierarchy Zoom is designed to make network depth feel spatial instead of modal. Zoom toward an HDA or subnet to reveal its internal graph, keep moving through deeper levels, then zoom back out to recover the larger structure without losing context.

An HDA X-Ray mode can expose internal relationships without forcing a full dive into the asset, making it easier to understand where a connection goes, how nested systems relate, and what part of a large asset you are actually looking at.

Continuous network zoom Inline HDA expansion HDA X-Ray Nested context preservation Semantic zoom

Technical development

Context-Aware IDE

A real coding environment inside the parameter workflow.

A Monaco-powered editor brings completion, signature help, hover documentation, symbol navigation, API information, and context-sensitive suggestions directly to VEX, OpenCL, Python, and C++ editing. The code stays next to the node and scene it affects.

The intelligence changes with the language and Houdini context: dedicated VEX semantics, Houdini-aware OpenCL bindings, HOM typing for Python, and C++/HDK integration with the native toolchain. It is four specialized environments sharing one editing surface, not one generic autocomplete layer.

VEX semantics OpenCL binding context Python + HOM typing C++ + HDK integration Completion & signatures Hover documentation Symbol navigation

Smarter middle-click

Pragmatic Node Info

MMB that tells you what changed, not only what exists.

Compare a node with available input data and surface attributes and groups that were created, modified, deleted, or left unchanged. Topology changes are called out separately so structural edits do not disappear inside a wall of statistics.

Memory deltas show where the footprint moved across attributes, groups, and VDBs. For VDB work, inspect reported tree, metadata, and transform touches alongside the volume state. The useful question becomes immediate: what did this node actually touch?

Attribute changes Group changes Topology changes Per-attribute memory delta Per-group memory delta VDB memory delta VDB touch state

Touch and revision indicators report changed state where available; they are not a per-element value diff.

Stop burning one shortcut per command

Context-Aware Action System

One key can resolve to the right operation for the current network and working state.

Build rules around network context, Ctrl/Alt/Shift/Space modifiers, and selected versus unselected state. The same configured key can resolve differently across supported network types instead of becoming another isolated shortcut to remember.

Rules can execute custom Python functions or expressions with the originating UI event, create operators, run supported recipes and shelf tools, or open custom menus at the cursor. When the built-in conditions are not enough, your Python can inspect Houdini and decide what should happen.

Network-context rules Modifier rules Selection-state rules Python event logic Operator creation Recipes & shelf tools Custom menus

Hardware pressure in peripheral vision

Resource Monitor

Live CPU, RAM, GPU, and VRAM telemetry inside the workspace.

Keep system pressure visible while you work through heavy simulations, large procedural scenes, GPU workflows, or memory-heavy assets. The HUD is designed to stay readable without becoming the center of the interface.

An optional cook timeline adds context about cook activity observed by Workflow. Choose from ring, liquid, segmented, ribbon, and thermal styles, then tune the presentation to fit the workspace.

CPU System RAM GPU VRAM Optional cook timeline Six gauge styles

Telemetry shows system pressure; it does not assign GPU or RAM usage to an individual node.

Follow the expensive work

Advanced Performance Profiler

Move from a hotspot into the recorded relationships behind it.

Start from expensive recorded work, then trace it through event call trees, bottom-up caller views, flame graphs, and direct node navigation. The point is not another timing table; it is a better way to investigate the capture.

Separate VEX program reports keep code-level investigation from getting buried inside general SOP evaluation. Move through callers and surrounding events, then jump back to the node you need to inspect.

Hotspot analysis Event call trees Bottom-up callers Event flame graphs VEX program reports Direct node navigation

Event analysis follows Houdini's captured performance data rather than source-level CPU sampling.

NETWORK ERGONOMICS

Optional ways to make the Network Editor itself feel better to use.

A classic returns

Bezier Network Wires

A classic network language, brought back with a modern implementation.

Houdini once offered true Bezier wire routing. Workflow restores that continuous curve language in the modern Network Editor with its own implementation.

Long connections read as flowing paths instead of rigid straight segments or rounded elbows. On dense graphs, the curves make branch direction easier to follow while bringing back a network style many Houdini artists still prefer.

True Bezier routing Custom implementation Smooth continuous paths Dense-graph readability Classic Houdini feel

Flame-style edit / result loop

Overlay Network Editor (ONE)

Edit the graph over the result.

Traditional pane layouts divide screen space between the network and the viewport. ONE layers the Network Editor directly over the 3D view, so both can use the same working area. Edit the graph and evaluate the result underneath it without repeatedly moving between separate visual zones.

Run fullscreen, keep a large viewport, overlay the graph, and keep the Parameter Workspace nearby for a compact Flame-inspired production loop. Adjust the network opacity, reveal or hide it quickly, and reclaim useful screen area on anything from a laptop to a large workstation display.

Network over viewport Shared screen area Fullscreen workflow Adjustable opacity Quick reveal / hide Parameter Workspace pairing

Native development

C++ & HDK Development

Go from toolchain setup to a verified native build inside the same environment.

Start the supported native-development setup from Workflow, guide the required compiler and environment configuration, then verify the result with a fresh HDK compile, native load, and function-call check.

The same C++ environment feeds Workflow's HDK-aware language intelligence. If you also use Pragmatic Operators, pair it with C++ Wrangle to write, compile, and iterate on native node logic directly in the scene.

Guided toolchain setup Real HDK compile check Native load verification C++ / HDK intelligence

In development · Investigation

Persistent Probes & Branch Experiments

Keep questions attached to the graph while you try another approach.

The planned probe system keeps selected data, diagnostics, or history attached to points in the network so an investigation survives beyond one click or one pane. Branch experiments extend that idea by making alternate approaches easier to duplicate, compare, and revisit.

Together with Graph Lenses and Graph Diffing, the goal is a Network Editor that helps reason about the graph, not just draw it.

Persistent probes Retained history Branch experiments Side-by-side reasoning

In development · Control evaluation

Cook Gate & Freeze Region

Experiment on one part of a network without constantly paying for everything downstream.

Cook Gate is designed to make temporary evaluation boundaries explicit in the graph. Freeze a known-good region, work on the branch you care about, and reopen the gate when you are ready to evaluate the larger dependency chain again.

The goal is safer, more deliberate iteration on expensive networks without turning manual bypassing, caching, and branch management into a separate debugging task.

Temporary cook boundaries Freeze known-good regions Focused branch iteration Explicit evaluation control

In development · Hidden relationships

Reference Lens & Connect to Bookmark

Make indirect dependencies visible and make long-distance graph work easier to navigate.

Reference Lens is designed to expose parameter references, indirect dependencies, and other relationships that are real but not represented by ordinary network wires. Connect to Bookmark complements that by making distant graph locations explicit destinations instead of coordinates you have to remember.

Reference visibility Indirect dependencies Named graph destinations Long-distance navigation

FAQ

Before you install.

Which Houdini versions and operating systems are supported?

Supported Houdini versions and operating systems will be published with the verified release before purchases open.

What is included with Workflow?

Workflow includes the shipping systems described in the main feature sections: High-Density Parameter Workspace, Context-Aware IDE, Pragmatic Node Info, Context-Aware Action System, Overlay Network Editor, Bezier Network Wires, Resource Monitor, Advanced Performance Profiler, C++ & HDK Development, and their supporting workflow tools. Graph Lenses, Visual Graph Diffing, Continuous Hierarchy Zoom / HDA X-Ray, Persistent Probes / Branch Experiments, Cook Gate / Freeze Region, and Reference Lens / Connect to Bookmark are labeled as in-development directions and are not current shipping claims. Pragmatic Operators is a separate product.

How does licensing work?

Individual licenses are assigned to one named customer, support one concurrent seat and up to two activated devices, and include 12 months of update coverage. Workflow is $199 Indie / $399 FX in year one, with $169 / $329 active renewal pricing. Eligible releases remain usable permanently. Studio licensing uses a floating concurrent seat pool sized to the purchased tier.

Can I customize the interface?

Yes. Verified options include density and layout, supported interaction preferences, overlay behavior, timeline interaction, Resource Monitor presentation, and other component-specific UI preferences. Available options vary by component.

How is Workflow different from Suite?

Workflow is the workspace and productivity product. Pragmatic Suite combines Workflow with Pragmatic Operators under the broader bundle offer. Operators is not included in a standalone Workflow license.
